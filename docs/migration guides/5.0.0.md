# Migrating from 4.x to 5.0.0

This guide covers breaking changes in 5.0.0.

## Party connections and IDs

Party operations now require **both XMPP and STOMP**. If you disabled either transport, enable it before creating or joining parties. Both are enabled by default:

```js
// 4.x: an integration might have disabled STOMP
const client = new Client({ connectToSTOMP: false });

// 5.0: keep both connections enabled for party operations
const client = new Client({ connectToXMPP: true, connectToSTOMP: true });
```

`client.joinParty(id)`, `party.join()` and `presenceParty.join()` now accept only an EOS party ID or a linked Fortnite lobby ID. Obtain a current ID from the party or presence instead of reusing an older, unlinked party ID. A `Party` exposes `party.eosId` for EOS and `party.id` for the linked Fortnite lobby; these are different IDs.

```js
// 4.x: an old stored Fortnite party ID could be used
await client.joinParty(oldPartyId);

// 5.0: use a current EOS party ID or linked Fortnite lobby ID
await client.joinParty(party.eosId);
// Alternatively: await client.joinParty(party.id);
```

A `PresenceParty` may be private or lack an ID; its `join()` method rejects in that case. An old ID that is not an EOS ID or linked lobby ID cannot be converted by `joinParty()`.

## Fetching and constructing parties

The `raw` argument to `getParty()` was removed. Use the raw Fortnite method when you need a lobby payload, or `getParty()` for a `Party` instance:

```js
// 4.x
const rawLobby = await client.getParty(lobbyId, true);

// 5.0: lobbyId is a linked Fortnite lobby ID
const rawLobby = await client.getRawFortniteParty(lobbyId);
const party = await client.getParty(lobbyId); // Also accepts an EOS party ID
```

If you construct `Party` or `ClientParty` yourself, both the Fortnite lobby and EOS party payloads are now required. Prefer `client.getParty()` when you only need a `Party` instance.

```js
// 4.x
const party = new Party(client, rawLobby);

// 5.0: lobbyId and eosId identify the same linked party
const rawLobby = await client.getRawFortniteParty(lobbyId);
const rawEOSParty = await client.eosParty.getParty(eosId);
const party = new Party(client, rawLobby, rawEOSParty);
// ClientParty likewise takes (client, rawLobby, rawEOSParty).
```

`Party#updateData()` was renamed for Fortnite updates. EOS updates have a separate method and payload:

```js
// 4.x
party.updateData(fortniteUpdate);

// 5.0
party.updateFortniteData(fortniteUpdate);
// For an EOS party payload instead: party.updateEOSData(eosPartyData);
```

## Party leader and leaving

`PartyMember#role` was removed. Use `isLeader` for a member or `party.leader` to find the leader. Other role strings have no replacement.

```js
// 4.x
if (member.role === 'CAPTAIN') handleLeader(member);
const leader = party.members.find((member) => member.role === 'CAPTAIN');

// 5.0
if (member.isLeader) handleLeader(member);
const leader = party.leader; // May be undefined
```

`client.leaveParty()` now throws `PartyNotFoundError` when the client has no party. Guard the call if your code relied on the previous no-op:

```js
// 4.x: safe to call when client.party is absent
await client.leaveParty(false);

// 5.0
if (client.party) await client.leaveParty(false);
```

The `false` argument leaves without creating a replacement party. Omit it if you want the usual replacement party.

## Member joined events and metadata

`party:member:joined` now reports roster membership without waiting for a member state update. Cosmetics and readiness might not be populated when it fires. Handle metadata in `party:member:updated` instead:

```js
// 4.x
client.on('party:member:joined', (member) => {
  console.log(member.outfit, member.isReady);
});

// 5.0
client.on('party:member:joined', (member) => {
  console.log(`${member.displayName} joined`);
});
client.on('party:member:updated', (member) => {
  console.log(member.outfit, member.isReady);
});
```

Updates can occur more than once, and metadata received before the roster entry can be applied before the joined event. Do not assume exactly one update follows each join; coordinate events in your application if it needs both membership and metadata.

## Invitations

`invitation.party` is now optional. Use `eosPartyId` when only the ID is needed, or fetch the party when its details are needed:

```js
// 4.x
console.log(invitation.party.id);

// 5.0
console.log(invitation.eosPartyId);
const party = await invitation.fetchParty();
console.log(party.id); // Linked Fortnite lobby ID
```

`fetchParty()` does not work for private parties and can fail if the party is no longer available. A received invitation can still be accepted or declined without fetching its party: `await invitation.accept()` or `await invitation.decline()`.

`SentPartyInvitation#abort()` was removed. Remove calls to it; there is no supported replacement for cancelling an outgoing invitation. Declining a received invitation is a different operation.

## Party chat

`PartyChat#conversationId` is now the Fortnite lobby ID without the `p-` prefix. Update comparisons, stored IDs and code that constructs conversation IDs; do not substitute the EOS party ID.

```js
// 4.x
const conversationId = `p-${client.party.id}`;

// 5.0
const conversationId = client.party.chat.conversationId; // Same as client.party.id
await client.party.chat.send('Hello!');
// Alternatively: await client.party.sendMessage('Hello!');
```

The deprecated `PartyChat` members `jid`, `nick`, `joinLock`, `isConnected`, `join()`, `leave()` and `ban()` were removed. Remove XMPP room lifecycle and JID/nickname handling; party chat is managed by the client. Use `party.chat.send()` or `client.party.sendMessage()` to send messages. For transport connectivity, `client.stomp.isConnected` reports STOMP connectivity, not a per-chat connection state.

`ClientParty#chatBan()` was also removed, with no supported chat-ban replacement. Do not use `PartyMember#chatBan()` as a substitute: it cannot ban through the removed party method.

## Presence fields

Remove uses of `FriendPresence#hasVoiceSupport`, `FriendPresence#gameSessionJoinKey`, `PresenceParty#typeId` and `PresenceParty#key`. They have no direct replacements. `FriendPresence#sessionId` is a session ID, not a replacement for a game-session join key. If you need the available party details, use the remaining `PresenceParty` fields such as `id`, `size`, `appId` and `buildId`; these may be absent, especially for private parties.

## Removed events

`xmpp:presence:error` and `xmpp:chat:error` were removed. Presence and chat messages are processed by STOMP; use `stomp:message:error` for processing failures. It also reports other STOMP message processing failures, so it is not a presence- or chat-specific replacement. `xmpp:message:error` remains available for XMPP message processing failures.

```js
// 4.x
client.on('xmpp:presence:error', handleError);
client.on('xmpp:chat:error', handleError);

// 5.0
client.on('stomp:message:error', handleError);
```

`party:member:disconnected` was removed, with no direct replacement for a transient disconnect. If your application needs to react to a member's departure, handle the relevant final events instead:

```js
// 4.x
client.on('party:member:disconnected', handleDisconnect);

// 5.0: these indicate different final outcomes, not a transient disconnect
client.on('party:member:left', handleDeparture);
client.on('party:member:expired', handleDeparture);
client.on('party:member:kicked', handleDeparture);
```

## TypeScript payload types

The following exported types were renamed. They describe Fortnite party data; runtime classes such as `Party` and `PartyMember` keep their names.

| 4.x | 5.0 |
| --- | --- |
| `PartyMemberSchema` | `FortnitePartyMemberSchema` |
| `PartySchema` | `FortnitePartySchema` |
| `PartyPrivacy` | `FortnitePartyPrivacy` |
| `PartyOptions` | `FortnitePartyOptions` |
| `PartyConfig` | `FortnitePartyConfig` |
| `PartyMessageData` | `FortnitePartyMessageData` |
| `PartyMemberData` | `FortnitePartyMemberData` |
| `PartyMemberUpdateData` | `FortnitePartyMemberUpdateData` |
| `PartyData` | `FortnitePartyData` |
| `PartyUpdateData` | `FortnitePartyUpdateData` |
| `PartyMemberIsland` | `FortnitePartyMemberIsland` |
| `PresencePartyData` | `FortnitePartyPresenceData` |

```ts
// 4.x
import type { PartyData, PresencePartyData } from 'fnbr';

// 5.0
import type { FortnitePartyData, FortnitePartyPresenceData } from 'fnbr';
```

`EOSPresenceInGame` was removed. Choose a type matching the data you consume: `EOSPresencePerNs` for one namespace entry, `EOSPresencePropsInGame` for its properties, or `EOSPresenceUpdateMessage` for the full update message. These are not drop-in aliases; update code for their respective shapes.
